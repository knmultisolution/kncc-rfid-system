# KNCC RFID System – Update 2026-10-04

## 1. RFID UID + signal profile
- ESP32 sends RFID UID plus RC522 diagnostic profile to `/api/device/scan`.
- The first valid scan saves the card signal profile and still creates attendance.
- Later scans verify both UID and the saved stable signal profile before attendance processing.
- Every physical scan is permanently stored in `attendance_scan_events` (valid, duplicate, invalid, mismatch).
- Logical attendance rows also keep RFID UID/signal profile/fingerprint and link back to the scan event.
- A classic RC522 does not provide a reliable true RSSI value. The stored signal is a card/read profile (UID size, SAK, PICC type, plus reader diagnostics).

## 2. Easier student + RFID management
- Students: fast client-side search, class/status filters, result counts, row numbers, detail view, RFID display, CSV import/export, and import template.
- RFID Cards: fast search, status filter, result counts, row numbers, signal status, card detail view, CSV import/export, and import template.
- Attendance: separate Attendance and Scan Activity tabs, counts, search, verification filters, row numbers, signal status, and scan detail view.
- Dashboard: raw scan and invalid/mismatch counts added.
- Live Attendance: listens to `attendance_scan_events`, so every physical scan can appear live.

## 3. Import / export
- CSV downloads use browser Blob downloads with UTF-8 BOM for Excel compatibility.
- Student import accepts aliases for common column names and can match a class by class label or class_id.
- RFID card import accepts student_code or index_number.
- Exports reflect the currently filtered list on Students/RFID Cards and the current report filter on Reports.

## 4. Professional reports
- Reports page has a Scan Activity report.
- A4 print layout with school logo, report title, period, summary counts, and clean tables.
- Use **Download / Save PDF** and select the browser's PDF destination.
- Scan Activity CSV export includes UID, verification, signal fingerprint, attendance type/status, student, and device.

## 6. Firmware
Use:

`firmware/KNCC_RFID_SIGNAL_FAST/`

Set these placeholders in `src/main.cpp` before upload:
- `YOUR_WIFI_SSID`
- `YOUR_WIFI_PASSWORD`
- `YOUR_DEVICE_API_SECRET`

The fast firmware gives immediate physical green feedback before the network verification call and retains pending scans in RAM for retry while connectivity is unavailable. RAM is not persistent across power loss.
